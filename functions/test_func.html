Функция test()

Логичная структура с принципом «early return»

Разбор работы функции — главного контроллера викторины,
построенной как линейный алгоритм из 5 шагов

Полный код функции

def test():
    '''возвращает страницу вопроса'''
    
    # 1. Защита: если викторина не выбрана — на главную
    if 'quiz' not in session or int(session['quiz']) < 0:
        return redirect(url_for('index'))
    
    # 2. Если пришёл ответ — сохраняем его
    if request.method == 'POST':
        save_answers()
    
    # 3. Достаём следующий вопрос
    next_question = get_question_after(session['last_question'], session['quiz'])
    
    # 4. Если вопросы кончились — на страницу результатов
    if not next_question:
        return redirect(url_for('result'))
    
    # 5. Иначе — показываем вопрос
    return question_form(next_question)

5 пронумерованных шагов — каждый выполняет одну задачу

Принцип «early return»

💡 Ключевая идея

Сначала обрабатываем исключительные ситуации и выходим из функции,
затем пишем основной сценарий как плоский линейный код.

Как это работает в test():

  • Шаг 1 — ранний выход, если нет викторины
  • Шаг 4 — ранний выход, если вопросы кончились
  • Шаг 5 — единственный «нормальный» возврат с HTML

Благодаря этому основной код не находится внутри вложенных if/else — он читается сверху вниз как последовательность действий.

Шаг 1. Защита от некорректного входа

1 Проверка: выбрал ли пользователь викторину? 
if 'quiz' not in session or int(session['quiz']) < 0:
    return redirect(url_for('index'))

Что проверяется:

  • Есть ли ключ 'quiz' в сессии?
  • Значение >= 0? (отрицательное означает «не выбрана»)

Результат:

Если условие истинно — ранний возврат: пользователь перенаправляется на главную страницу, где может выбрать викторину. Функция завершается.

Шаг 2. Обработка ответа пользователя

2 Проверка: пришёл ли ответ (POST-запрос)? 
if request.method == 'POST':
    save_answers()

Логика:

  • POST → пользователь нажал «Ответить» → вызываем save_answers()
  • GET → просто зашёл на страницу → пропускаем этот блок

💡 Особенность

Здесь нет else и нет return. После обработки POST поток просто продолжается дальше — к получению следующего вопроса. Это делает код плоским.

Шаг 3. Получение следующего вопроса

3 Основной шаг: достаём вопрос из базы данных 
next_question = get_question_after(
    session['last_question'], 
    session['quiz']
)

Что делает функция:

  • Берёт ID последнего отвеченного вопроса из session['last_question']
  • Ищет в БД вопрос с ID больше этого значения
  • Фильтрует по текущей викторине session['quiz']

Результат:

Переменная next_question содержит кортеж с данными вопроса или None/пустой список, если вопросов больше нет.

Шаг 4. Проверка окончания викторины

4 Проверка: есть ли ещё вопросы? 
if not next_question:
    return redirect(url_for('result'))

Условие not next_question:

  • Истинно, если значение None
  • Истинно, если список пустой
  • Истинно для любого «ложного» объекта

Результат:

Если вопросов больше нет — ранний возврат: пользователь перенаправляется на страницу результатов. Функция завершается.

Шаг 5. Возврат страницы вопроса

5 Основной возврат: показываем вопрос пользователю 
return question_form(next_question)

Что делает question_form():

  • Берёт текст вопроса из кортежа
  • Собирает варианты ответов
  • Перемешивает их через shuffle()
  • Рендерит шаблон test.html
  • Возвращает HTML в браузер

💡 Единственный «нормальный» выход

Это единственный случай, когда функция возвращает HTML. Все остальные выходы — это redirect на другие страницы.

Поток выполнения

Функция имеет 3 возможных выхода и 1 основной путь:

→ Пользователь заходит на /test (GET или POST)
1 Нет викторины в session? → redirect на /
2 POST-запрос? → save_answers() → продолжаем
3 Получаем следующий вопрос из БД
4 Вопросов нет? → redirect на /result
5 Вопрос есть → return HTML с вопросом

Все шаги идут последовательно — код читается как линейный алгоритм

Преимущества такой структуры

📖 Читаемость

Код читается как последовательность шагов. Каждый блок — одна логическая единица.

🎯 Плоская структура

Максимум 1 уровень вложенности. Не нужно следить за отступами и скобками.

🔧 Простота отладки

Легко поставить breakpoint на любом шаге. Поток выполнения предсказуем.

🐍 Pythonic

Использует идиомы Python: not in, not next_question, early return.

🛡️ Защита

Исключительные ситуации обрабатываются первыми — основной код защищён от ошибок.

📝 Документирование

Нумерованные шаги позволяют легко комментировать и документировать код.
