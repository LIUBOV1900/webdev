Как устроен Веб? (Повторение)

👤 Клиент (Браузер)

Запрашивает информацию. Отправляет HTTP-запрос по адресу (URL).

🖥️ Сервер

Принимает запрос, обрабатывает его и отправляет обратно HTTP-ответ (HTML-страницу).

URL — это как адрес дома.
https://site.com/test
Протокол (https) → Домен (site.com) → Путь (/test).

Статический vs Динамический сайт

📄 Статический сайт

  • Сервер просто хранит готовые HTML-файлы.
  • Отдает один и тот же файл всем посетителям.
  • Пример: Визитка, инструкция.

⚙️ Динамический сайт (Веб-приложение)

  • Сервер передает запрос в Программу (Приложение).
  • Программа берет данные из Базы Данных.
  • Программа на лету собирает уникальный HTML.
  • Пример: Соцсети, интернет-магазины, наша Викторина.

Знакомство с Flask 🌶️

Flask — это библиотека для языка Python, которая превращает вашу обычную программу в веб-сервер.

Аналогия: Если Python — это ваш мозг, то Flask — это уши и рот, которые позволяют вашему мозгу слышать запросы из браузера и отвечать на них.

Flask называется микрофреймворком, потому что он очень простой и дает только базовые инструменты, не навязывая лишних правил.

Первый запуск Flask

Любое Flask-приложение начинается с создания объекта app и его запуска.

from flask import Flask

# Создаем объект веб-приложения
app = Flask(__name__)

# Запускаем веб-сервер
if __name__ == '__main__':
    app.run()

Что здесь происходит?
Flask(__name__) говорит Flask'у: "Используй имя этого файла, чтобы находить шаблоны и ресурсы".
app.run() запускает бесконечный цикл ожидания запросов от браузеров.

Маршрутизация (URL Rules)

Как сервер понимает, какую функцию запустить при запросе адреса /test? Мы должны связать URL и Функцию.

# Связываем адрес '/' с функцией index
app.add_url_rule('/', 'index', index)

# Связываем адрес '/test' с функцией test
app.add_url_rule('/test', 'test', test)
Маршрутизация — это как настройка переадресации на телефоне. "Если звонят на номер /test — соединяй с функцией test()".

Представления (Views)

VIEW (Представление) — это функция, которая формирует ответ для браузера.

def index():
    return "<h1>Добро пожаловать в Викторину!</h1>"

def test():
    return "<p>Здесь будет вопрос...</p>"

Функция обязана вернуть строку (HTML-код, текст или JSON). Именно эту строку сервер отправит в браузер.

Навигация: Ссылки vs Перенаправление

🔗 Ссылка (Выбор пользователя)

Сервер отправляет HTML с тегом <a>. Пользователь сам решает, кликнуть или нет.

return '<a href="/test">Начать</a>'

🚀 Перенаправление (Решение сервера)

Сервер сам говорит браузеру: "Срочно иди на другой адрес!". Пользователь даже не замечает подмены.

from flask import redirect, url_for

return redirect(url_for('result'))

Структура нашего приложения (Викторина)

Наш сайт будет состоять из трех логических страниц (ресурсов):

1. Старт

url: '/'

Функция index()

Выбор викторины и старт

2. Тест

url: '/test'

Функция test()

Показ вопросов по одному

3. Финиш

url: '/result'

Функция result()

Итоги и количество баллов

⚠️ Главная ловушка новичка

Нам нужно хранить номер текущего вопроса и счетчик баллов. Первая мысль — использовать глобальные переменные:

current_question_id = None
score = 0

def test():
    global score
    score += 1 # Увеличиваем счетчик

Почему это сломается?

Веб-сервер работает для всех пользователей одновременно в одном процессе!

Если Вася и Петя одновременно зайдут на сайт, они будут менять одну и ту же переменную score. Они будут мешать друг другу!

Решение: Сессии (Sessions) 🔐

Нам нужно дать каждому пользователю свой личный "сейф" для хранения данных.

Аналогия: Глобальная переменная — это одна доска в классе, где все пишут мелом одновременно.
Сессия — это личный блокнот у каждого ученика. Вася пишет в свой, Петя — в свой.

Во Flask есть встроенный объект session, который работает как словарь (ключ-значение), но отдельный для каждого браузера.

Работа с session в коде

from flask import session

def test():
    # Читаем данные из "личного блокнота" пользователя
    score = session.get('score', 0)
    
    # Обновляем данные
    session['score'] = score + 1
    session['question_id'] = 5

Flask сам понимает, кто обратился к сайту, и подставляет данные именно этого клиента.

Секретный ключ и Cookie 🍪

🔐 SECRET_KEY

Данные сессии нужно шифровать, чтобы пользователь не мог их подделать в браузере.

Flask потребует от вас задать секретный ключ:

app.config['SECRET_KEY'] = 'МойСекретныйКлюч123'

🍪 Как это работает? (Cookie)

Сервер выдает браузеру "пропуск" (Cookie) с зашифрованным ID сессии.

При каждом следующем клике браузер показывает этот "пропуск" охраннику (серверу), и сервер понимает: "Ага, это снова Вася, достаньте его блокнот!".

Итоги урока

  • Flask позволяет писать веб-серверы на Python.
  • Маршрутизация (add_url_rule) связывает URL-адреса с функциями.
  • View (Представление) — это функция, которая возвращает HTML для браузера.
  • Глобальные переменные в вебе не работают, так как они общие для всех пользователей.
  • Сессии (session) и Cookie позволяют хранить личные данные каждого пользователя отдельно.
