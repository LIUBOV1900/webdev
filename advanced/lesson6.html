HTTP-методы: GET и POST

Когда браузер отправляет запрос на сервер, он указывает метод — то есть говорит, как именно он хочет взаимодействовать.

📥 GET (Получить)

Изначально создан для получения данных. Но может и передавать их.

Пример: Открытие страницы, переход по ссылке.

📤 POST (Отправить)

Создан специально для отправки данных на сервер (формы, логины, файлы).

Пример: Отправка ответа в тесте, оплата товара.

Метод GET: Данные в URL

При методе GET все дополнительные данные «приписываются» прямо к адресу (URL) через знак ?.

GET /search?q=flask&lang=ru HTTP/1.1

✅ Плюсы

  • Можно сохранить ссылку в закладки.
  • Можно поделиться ссылкой с другом.

❌ Минусы

  • Видны всем (в адресной строке, в истории).
  • Ограничение по размеру (около 2000 символов).
  • Нельзя передать сложные данные или файлы.

Метод POST: Данные в «теле»

При методе POST URL остается чистым, а все данные прячутся внутри тела (body) HTTP-запроса.

POST /login HTTP/1.1
...заголовки...

username=admin&password=12345 <-- Тело запроса

🏆 Почему мы будем использовать POST?

  • Безопасность: Данные (например, пароли) не светятся в адресной строке.
  • Объем: Нет жестких ограничений на размер передаваемых данных.
  • Удобство: Можно передавать сложные структуры и файлы.

HTML-формы: Интерфейс для ввода

Чтобы пользователь мог ввести данные, мы размечаем на странице форму. Все элементы, которые нужно отправить, оборачиваются в тег <form>.

<form method="POST" action="/test">
    
    <!-- Сюда мы поместим поля ввода -->

</form>

📍 Атрибут action

Куда отправляем данные? (URL ресурса, который будет их обрабатывать).

🚀 Атрибут method

Каким методом отправляем? (В нашем случае всегда "POST").

Элементы ввода и пары «Имя-Значение»

Каждый элемент формы должен иметь атрибут name. Именно по этому имени Flask будет искать данные!

Текст и Кнопки

<!-- Однострочное поле -->
<input type="text" name="login">

<!-- Многострочное поле -->
<textarea name="comment"></textarea>

Выбор вариантов

<!-- Переключатели (только один) -->
<input type="radio" name="q1" value="a">

<!-- Флажки (можно несколько) -->
<input type="checkbox" name="hobby" value="sport">

На сервер улетают пары: name="login" → value="Вася".

Выпадающие списки и Кнопка отправки

📋 Выпадающий список

Удобно, когда вариантов много. Внутри <select> лежат <option>.

<select name="quiz_id">
  <option value="1">Викторина 1</option>
  <option value="2">Викторина 2</option>
</select>

🚀 Кнопка отправки (Submit)

Именно этот элемент «собирает» все данные из формы и отправляет их на сервер по адресу из action.

<input type="submit" value="Начать тест!">

<!-- Или современная кнопка: -->
<button type="submit">Отправить</button>

Читаем данные во Flask: объект `request`

Когда браузер отправляет POST-запрос, Flask «ловит» его и кладет всю информацию в специальный объект — request (запрос).

from flask import request

def test():
    # Смотрим, каким методом пришел запрос
    if request.method == 'POST':
        # Обработка отправленных данных
        pass
    else:
        # Если просто зашли на страницу (GET)
        pass

Объект request живет только внутри одной функции-view и содержит данные именно текущего клиента.

Достаем значения из формы

Если форма была отправлена методом POST, все пары «имя-значение» попадают в словарь request.form.

from flask import request

def index():
    if request.method == 'POST':
        # Достаем значение по атрибуту name из HTML
        quiz_id = request.form.get('quiz_id')
        
        # Сохраняем в сессию пользователя
        session['quiz_id'] = quiz_id
        
        return redirect(url_for('test'))
Важно: Метод .get('имя') безопаснее, чем прямое обращение ['имя']. Если пользователь не выбрал ничего, .get() вернет None, а не вызовет ошибку crashes.

Разрешаем методы в Flask

По умолчанию Flask-маршруты принимают только GET-запросы. Если мы отправим на такой адрес POST-форму, сервер выдаст ошибку 405 Method Not Allowed.

Нужно явно разрешить POST в правиле URL:

# Добавляем необязательный параметр methods
app.add_url_rule(
    '/', 
    'index', 
    index, 
    methods=['GET', 'POST'] # <-- Разрешаем оба метода
)

Теперь функция index() будет срабатывать и при первом заходе (GET), и при отправке формы (POST).

Практика: Логика главной страницы

Функция index() теперь работает как «развилка» в зависимости от метода:

📥 Если GET (первый заход)

  • Берем из БД список всех викторин.
  • Генерируем HTML-код с формой (<form>) и выпадающим списком (<select>).
  • Возвращаем этот HTML пользователю.

📤 Если POST (нажали кнопку)

  • Читаем ID выбранной викторины: request.form.get('quiz').
  • Кладем ID в сессию: session['quiz'] = ....
  • Делаем redirect на страницу /test.

⚠️ Защита от ошибок (Хакер-режим)

Что если пользователь — хитрый и вручную вбил в адресную строку site.com/test, не выбрав викторину?

Проблема

В сессии нет quiz_id. Код попытается найти вопросы для несуществующей викторины и упадет с ошибкой!

Решение: Проверка на странице /test

def test():
    if 'quiz' not in session:
        # Если викторина не выбрана, выгоняем на главную
        return redirect(url_for('index'))
    
    # ... остальной код показа вопроса ...

Итоги урока

  • HTTP-методы: GET для получения (данные в URL), POST для отправки (данные в теле). Мы используем POST.
  • HTML-формы: Тег <form> с атрибутами method и action собирает данные пользователя.
  • Элементы ввода: У каждого должен быть уникальный атрибут name, по которому мы ищем данные.
  • Объект request: Позволяет во Flask проверить метод (request.method) и прочитать данные (request.form.get()).
  • Безопасность: Всегда проверяйте, есть ли нужные данные в сессии, перед их использованием!
