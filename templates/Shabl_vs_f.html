От f-строк к шаблонам

Эволюция генерации HTML в Python-приложениях

Цель

Показать, почему профессионалы переходят от f-строк к шаблонам, и как это делает код чище и удобнее.

Подход 1: Генерация через f-строки

HTML собирается внутри Python-функции.

def quiz_form(): """Получает список викторин и генерирует HTML""" q_list = get_quises() if not q_list: return "<html><body><h2>Викторины пока не добавлены.</h2></body></html>" options_html = "" for q_id, q_name in q_list: options_html += f'<option value="{q_id}">{q_name}</option>\n' final_html = f"""<html><body><h2>Выберите викторину:</h2> <form method="post" action="/index"> <select name="quiz">{options_html}</select> <p><input type="submit" value="Выбрать"></p> </form></body></html>""" return final_html.strip()

Подход 2: Шаблоны (Jinja2)

Python передаёт данные, HTML — в отдельном файле.

<!DOCTYPE html> <html> <head> <meta charset="UTF-8"> <link rel="stylesheet" href="{{ url_for('static', filename='style.css') }}"> <title>Викторина</title> </head> <body> <h2>Выберите викторину:</h2> <form method="post" action="/"> <select name="quiz"> {% for id, name in q_list %} <option value="{{ id }}">{{ name }}</option> {% endfor %} </select> <p><input class="btn" type="submit" value="Выбрать"></p> </form> </body> </html>

Параллельное сравнение

f-строки
def quiz_form(): q_list = get_quises() options = "" for id, name in q_list: options += f'<option...>{name}</option>' return f"<html>...{options}...</html>"
⚠️ Проблемы:
  • HTML внутри Python
  • Сложно читать
  • Трудно менять дизайн
🎨
Шаблоны
Python:
def quiz_form(): q_list = get_quises() return render_template('quiz.html', q_list=q_list)
HTML:
{% for id, name in q_list %} <option value="{{ id }}">{{ name }}</option> {% endfor %}
✅ Преимущества:
  • Чистый Python-код
  • HTML отдельно
  • Легко менять дизайн

Почему шаблоны — стандарт?

✅ Преимущества

  • Читаемость кода
  • Frontend может менять HTML без знания Python
  • Автоматическое экранирование (защита от XSS)
  • Переиспользование шаблонов
  • Масштабируемость проекта

⚠️ Недостатки f-строк

  • Смешение логики и представления
  • Хрупкость кода
  • Сложность изменений дизайна
  • Нет подсветки HTML в строках
  • Риск XSS-атак
Когда что использовать?

f-строки: простые скрипты, быстрые прототипы.

Шаблоны: веб-приложения, командная работа.

🔑 Главное правило

Разделяй логику (Python) и представление (HTML).
Это делает код чистым и готовым к росту.
